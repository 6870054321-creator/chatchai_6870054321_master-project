# ADR-001: ตำแหน่งของการตรวจสอบตัวระบุ

- **สถานะ:** Proposed — รอการตัดสินใจในขั้นตอน 7.5
- **วันที่:** –
- **ผู้ตัดสินใจ:** ผู้วิจัย (ทบทวนกับอาจารย์ที่ปรึกษา)

## บริบท
ผลทดสอบ T-10 และ T-11 ของระบบปัจจุบันได้ 302 ทั้งคู่ คือไม่มีการตรวจสอบตัวระบุที่จุดรับคำขอ ส่วนระบบสำหรับสมาชิกสร้าง GTIN อัตโนมัติ ข้อมูลที่ลงทะเบียนผ่านช่องทางปกติจึงถูกต้องอยู่แล้ว

## ทางเลือกที่พิจารณา
1. ตรวจที่เส้นทางอ่านเท่านั้น (ชั้นที่ 2)
2. ตรวจที่เส้นทางเขียนเท่านั้น (Link Ingest API)
3. ตรวจทั้งสองเส้นทางด้วยโมดูลเดียวกัน

## พฤติกรรมของต้นแบบในปัจจุบัน (ชั่วคราว)
ต้นแบบใช้ทางเลือก 3: `src/pipeline/validator.js` ถูกเรียกจากทั้งท่อประมวลผลและ `src/ingest/ingestApi.js`

## หลักฐานที่ใช้ตัดสินใจ
T-10, T-11, S-02 และ unit test `identifier rules are shared with stage 2`

## การตัดสินใจ
_(ยังไม่ตัดสินใจ — ระบุทางเลือกที่เลือกและข้อกำหนดของมาตรฐานที่อ้างอิง)_
