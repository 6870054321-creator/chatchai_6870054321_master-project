# ADR-009: การย้อนกลับจากระดับตัวขยายกุญแจไปยังระดับ GTIN

- **สถานะ:** Accepted
- **วันที่:** 2026-11-02
- **ผู้ตัดสินใจ:** ผู้วิจัย (ทบทวนกับอาจารย์ที่ปรึกษา)

## บริบท

GS1 Digital Link รองรับ URL ที่มี qualifier (ตัวขยายกุญแจ) เพื่อระบุ instance เฉพาะของสินค้า เช่น:

```
/01/08850999000014/10/LOT123      ← ระดับ lot (รุ่นการผลิต)
/01/08850999000014/21/SN456       ← ระดับ serial number
/01/08850999000014                ← ระดับ GTIN
```

หาก linkset ระดับ qualifier ไม่ถูกลงทะเบียนไว้ (เช่น มี `/01/08850999000014` แต่ไม่มี `/01/08850999000014/10/LOT123`) ระบบควรทำอย่างไร?

สถานการณ์นี้พบบ่อยในสภาพแวดล้อมจริง เพราะผู้ผลิตบางรายลงทะเบียนเฉพาะระดับ GTIN โดยไม่แยกตาม lot หรือ serial

## ทางเลือกที่พิจารณา

1. **ย้อนกลับทีละระดับจนถึงระดับ GTIN** ✓
   - ลอง `/01/{gtin}/10/{lot}` → ถ้าไม่มี ลอง `/01/{gtin}` → ถ้าไม่มี ตอบ 404
   - ข้อดี: ผู้ใช้ได้ผลลัพธ์ที่เป็นประโยชน์แม้ข้อมูล lot-level ไม่มี

2. **ตอบ 404 ทันที**
   - ตรง strict กับ request ที่ถามมา
   - ข้อเสีย: ผู้บริโภคที่สแกน QR code บนสินค้าจะได้ 404 แม้สินค้านั้นมีข้อมูลระดับ GTIN

3. **ย้อนกลับเฉพาะบางประเภทลิงก์**
   - เช่น fallback เฉพาะ `gs1:pip` (product information page) แต่ไม่ fallback `gs1:traceability`
   - ข้อดี: precise ข้อเสีย: ซับซ้อน ยากต่อการ document และทดสอบ

## พฤติกรรมของต้นแบบในปัจจุบัน

`src/pipeline/linksetResolver.js` ทำ fallback ทีละระดับ:
1. หา linkset ตาม full path (รวม qualifier ทั้งหมด)
2. ถ้าไม่มี ตัด qualifier สุดท้ายออก แล้วลองใหม่
3. ทำซ้ำจนถึงระดับ GTIN
4. ถ้าระดับ GTIN ก็ไม่มี ตอบ 404

## หลักฐานที่ใช้ตัดสินใจ

| กรณีทดสอบ | เงื่อนไข | ผลที่คาดหวัง |
|---|---|---|
| T-08 | `/01/{gtin}/10/LOT_KNOWN` — มี linkset ระดับ lot | 307 → URL ระดับ lot |
| T-08 variant | `/01/{gtin}/10/LOT_UNKNOWN` — ไม่มี lot นี้ | fallback → 307 → URL ระดับ GTIN |
| กรณีเสริม S-04 | `/01/{gtin}/21/{serial}` — ไม่มี serial | fallback → 307 → URL ระดับ GTIN |
| Edge case | `/01/{gtin}` — ไม่มีข้อมูลเลย | 404 |

## การตัดสินใจ

**เลือกทางเลือกที่ 1:** ย้อนกลับทีละระดับจนถึงระดับ GTIN

GS1 Digital Link Technical Standard §10.3 แนะนำให้ resolver ทำ qualifier fallback เพื่อ improve discoverability ผู้บริโภคที่สแกน QR code บนตัวสินค้า (ซึ่งมี lot/serial) ควรได้ข้อมูลสินค้าระดับ GTIN อย่างน้อย แทนที่จะได้ 404 ซึ่งไม่มีประโยชน์

## ผลที่ตามมา

**ข้อดี:**
- UX ดีสำหรับผู้บริโภคที่สแกน — ได้ผลลัพธ์ทุกครั้งที่สินค้ามี linkset ระดับ GTIN
- T-08 ผ่าน
- สอดคล้องกับ GS1 spec recommendation

**ข้อเสีย:**
- ผู้รับอาจไม่รู้ว่าได้ข้อมูลจาก fallback ระดับใด — ควรเพิ่ม header บอก เช่น `X-GS1-Resolved-Level: GTIN`
- อาจ mask ปัญหาที่ข้อมูล lot-level ไม่ถูก ingest

**สิ่งที่ต้องทำต่อ:**
- พิจารณาเพิ่ม response header `X-GS1-Resolved-Level` บอกว่า resolve ได้จากระดับใด
- Document fallback behavior ใน `.well-known/gs1resolver` resolver description
