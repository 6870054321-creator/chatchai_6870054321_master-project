# ADR-003: คำตอบสำหรับตัวระบุนอกช่วงเลขบ่งชี้บริษัท (T-11)

- **สถานะ:** Accepted
- **วันที่:** 2026-11-02
- **ผู้ตัดสินใจ:** ผู้วิจัย (ทบทวนกับอาจารย์ที่ปรึกษา)

## บริบท

ระบบนี้คือ GS1 Resolver ระดับชาติของไทย ที่รับผิดชอบเฉพาะ GCP prefix ที่ GS1 Thailand จัดสรร (ค่าเริ่มต้น: `885`) เมื่อได้รับ GTIN ที่ถูกต้องตามไวยากรณ์และ checksum แต่มี prefix ที่ไม่อยู่ใน `ALLOWED_PREFIXES` — ระบบต้องตอบสนองอย่างใดอย่างหนึ่ง

ตัวอย่าง: GTIN `09506000134352` (ตัวอย่างที่ GS1 ใช้ในเอกสาร prefix `950`) ถูกต้องตามไวยากรณ์และเลขตรวจสอบ แต่ไม่อยู่ในช่วง `885` ของ GS1 Thailand (กรณี T-11)

## ทางเลือกที่พิจารณา

1. **404 Not Found** ✓
   - บอกว่า resource ไม่มีอยู่ใน resolver นี้
   - ตรงไปตรงมา ไม่บอกให้ client ไปหาที่อื่น

2. **400 Bad Request**
   - บอกว่า request มีปัญหา — ไม่ถูกต้อง เพราะ GTIN นั้นถูกต้องตาม GS1 General Specifications ทั้งไวยากรณ์และเลขตรวจสอบ
   - แค่ resolver นี้ไม่มีอำนาจ (authority) เหนือ prefix นั้น

3. **เปลี่ยนเส้นทางไปยังรีโซลเวอร์ระดับโลก (id.gs1.org)**
   - ข้อดี: ผู้ใช้ได้ผลลัพธ์ที่ถูกต้อง
   - ข้อเสีย: เพิ่ม dependency กับ external service, อาจ redirect วนซ้ำ, อยู่นอกขอบเขต POC

## พฤติกรรมของต้นแบบในปัจจุบัน

`src/pipeline/02_validator.js` ตรวจ prefix และ return error object ที่ `app.js` แปลงเป็น 404 response พร้อม body อธิบายเหตุผล

## หลักฐานที่ใช้ตัดสินใจ

| กรณีทดสอบ | ระบบที่เปรียบเทียบ | ผลที่ได้ |
|---|---|---|
| T-11 | ต้นแบบ | 404 |
| T-11 | GS1 Resolver CE | ยังไม่ได้รัน (จากซอร์สโค้ดคาดว่า 404 เพราะไม่พบข้อมูล ไม่ได้ตรวจช่วงเลขบ่งชี้บริษัท) |
| T-11 | ระบบ production (ถ้ามี) | TBD |

GS1-Conformant Resolver Standard [4] §2.4.1 และหมวด 5 ข้อ 8 กำหนดว่า เมื่อ URI ถูกต้องตามไวยากรณ์แต่รีโซลเวอร์ไม่มีข้อมูลของตัวระบุนั้น ต้องตอบ 404 (SHALL) ส่วน 400 ใช้เมื่อ URI ไม่ผ่านการตรวจไวยากรณ์ ตัวระบุนอกช่วงเลขบ่งชี้บริษัทเข้ากรณีแรก ผลของ Resolver CE ต้องยืนยันด้วยการรันในขั้นตอน 7.7

## การตัดสินใจ

**เลือกทางเลือกที่ 1: 404 Not Found**

400 Bad Request ไม่ถูกต้องเพราะ GTIN นั้นถูกต้องตาม GS1 General Specifications — ความผิดพลาดไม่ได้อยู่ที่ request แต่อยู่ที่ขอบเขตอำนาจของ resolver นี้ การ redirect ไป id.gs1.org อยู่นอกขอบเขต POC และเพิ่ม dependency ที่ไม่จำเป็น ดังนั้น 404 จึงเป็นคำตอบที่ตรงกับ §2.4.1 ของมาตรฐาน

## ผลที่ตามมา

**ข้อดี:**
- เป็นไปตามข้อ SHALL ใน §2.4.1 และหมวด 5 ข้อ 8 ของมาตรฐาน
- ง่าย ไม่มี external dependency
- response body สามารถอธิบายเหตุผลได้ (เช่น `"prefix '030' not in scope of this resolver"`)

**ข้อเสีย:**
- ผู้ใช้ไม่รู้ว่าต้องไป query resolver ที่ใด — อาจเพิ่ม `Link` header ชี้ไป id.gs1.org ในอนาคต

**สิ่งที่ต้องทำต่อ:**
- พิจารณาเพิ่ม `Link: <https://id.gs1.org>; rel="gs1:globalresolver"` ใน response header เพื่อ guide ผู้ใช้
